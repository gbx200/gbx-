## 1. 项目背景与目标
	实现一个图书管理系统，图书管理：图书借阅与归还，图书录入，图书的查询与检索，图书状态；用户管理：注册与登录，个人信息维护；
## 2. 用户角色分析
	1. 普通读者：
		1. 注册，登录，修改个人密码及基本信息
		2. 浏览图书列表，根据书名/作者/ISBN进行模糊搜索，查看图书详情（如库存状态）。
		3. 发起图书借阅请求，查看自己的当前借阅和历史借阅记录。
		4. 确认归还图书，查看是否产生逾期记录。
		后端权限控制策略 (DRF)：只能访问自己相关的数据；禁止访问管理端接口（如添加图书、删除用户）。
	2. 图书管理员：
		1. 包含读者权限：管理员通常也具备读者的所有功能（可以借书、查书）。
		2. 图书资产管理：录入新书（创建图书信息）。；修改图书信息（如更新库存、修改简介）。；下架/删除图书。
		3. 读者管理：查看所有读者列表。；禁用/启用违规读者账号。
		4. 全局数据查看：可以查看全系统的借阅记录（不仅限于自己的），用于日常盘点。
## 3. 功能需求列表（按优先级划分）
### 1.核心基础功能：
	1. 用户认证模块
		读者注册与登录（基于 JWT Token）。
		获取当前登录用户信息。
	2. 图书信息模块
		图书列表展示（支持分页）。
		图书检索（支持按书名、作者模糊搜索）。
		图书详情查看。
	3. 借阅业务模块
		发起借阅请求（需校验库存和借阅数量限制）。
		归还图书（更新借阅状态，计算是否逾期）。
		个人借阅记录查询（当前在借、历史借阅）。
	4. 个人中心模块
		查看与修改个人基本信息。
		修改登录密码。
### 2.管理与进阶模块：
	1. 后台管理模块（管理员专属）
		图书的增、删、改操作（录入新书、修改信息、下架图书）。
		读者账号管理（查看列表、禁用/启用违规账号）。
		全局借阅记录查看。
	2. 业务扩展模块
		借阅续期功能（在应还日期前允许续借一次）。
		逾期状态高亮与简单违约金计算。
### 3.其他模块：
	1. 数据可视化大屏
		统计并展示“月度借阅 Top10 图书”、“各分类图书占比”（前端配合 ECharts 实现）。
	2. 消息通知模块
		站内信提醒（如：预约的图书已到货、借阅即将逾期提醒）。
		数据导出功能
		管理员可将借阅记录或图书列表导出为 Excel 文件。
## 4. 非功能性需求（性能、安全、可用性等）
### 1. 性能需求 (Performance)

- **响应时间**：常规接口（如图书列表查询、借阅记录获取）的响应时间应控制在 **500毫秒** 以内；复杂查询（如全局统计报表）响应时间不超过 **2秒**。
- **并发能力**：系统需支持至少 **50个** 用户同时在线进行查询和借阅操作，页面加载无明显卡顿。
- **前端性能**：Vue3 项目打包后，首屏加载时间（FCP）应小于 **2秒**。通过路由懒加载（Lazy Loading）和组件按需引入，优化静态资源体积。
- **数据库性能**：针对高频查询字段（如图书的 `书名`、`作者`，借阅记录的 `用户ID`）建立**数据库索引**，确保在数据量达到万级时，查询性能不发生显著衰减。

### 2. 安全需求 (Security)

- **身份认证与授权**：采用 **JWT (JSON Web Token)** 机制进行用户身份验证，Token 设置合理的过期时间。后端接口严格执行基于角色的访问控制（RBAC），确保普通读者无法越权调用管理员接口。
- **数据传输安全**：生产环境全面启用 **HTTPS** 协议，防止用户密码、Token 等敏感信息在传输过程中被窃听或篡改。
- **密码存储**：严禁明文存储用户密码，必须使用安全的哈希算法（如 Django 内置的 PBKDF2 或 bcrypt）进行加密存储。
- **输入校验与防注入**：后端使用 DRF 的序列化器（Serializers）对所有前端传入的数据进行严格校验，防止 SQL 注入和跨站脚本攻击（XSS）。
- **跨域安全 (CORS)**：合理配置 Nginx 或 Django 的跨域策略，仅允许受信任的前端域名访问后端 API。

### 3. 可用性与易用性 (Usability)

- **界面规范**：前端采用 Element Plus 组件库，保持全站 UI 风格统一、排版整洁，符合现代后台管理系统的交互规范。
- **操作反馈**：所有异步请求（如提交借阅、删除图书）必须提供明确的加载状态（Loading）和操作结果提示（成功/失败消息）。
- **异常处理**：系统具备友好的错误提示机制。当发生网络异常或服务器错误时，前端应显示易于理解的提示信息，而非直接抛出代码报错。
- **响应式适配**：页面布局应具备良好的自适应能力，在主流分辨率（如 1920x1080, 1366x768）下均能正常显示，无错位或内容遮挡。

### 4. 可靠性与可维护性 (Reliability & Maintainability)

- **进程守护**：后端 Django 服务通过 Supervisor（或宝塔面板的进程守护功能）运行，确保服务在意外崩溃或服务器重启后能够**自动恢复**。
- **日志记录**：系统需记录关键操作日志（如用户登录、借阅/归还操作、管理员修改数据），便于问题排查和安全审计。
- **代码规范**：前后端代码遵循统一的编码规范，核心业务逻辑编写单元测试，保证代码的可读性和可维护性。
- **自动化部署**：依托阿里云云效流水线实现 CI/CD，确保代码从提交到上线的流程标准化、自动化，减少人为部署失误。
